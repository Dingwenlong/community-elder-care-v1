# 故障演练记录

演练日期：2026-08-24。以下动作只使用虚构数据和本地服务。

| 故障 | 页面或客户端状态 | 重试与去重 | 审计和资料结果 |
|---|---|---|---|
| 云端 AI 不可用 | 老人端显示固定危险提示或“AI 当前不可用”；求助按钮仍可用 | 危险词先由本地规则判断，不等待云端返回 | 不保存原始聊天内容；危险提示产生的结构化事件按请求编号去重 |
| SOS 时 API 暂时离线 | 老人端显示“尚未送达” | 恢复网络后点击“重新发送”，沿用原请求编号，只送达一次 | 离线队列保留到服务端确认；服务端只产生一条事件 |
| App 重复请求 | 第二次响应标记 `isDuplicate=true` | 服务端返回第一次生成的签到或事件 | 数据库只有一条业务记录，审计不增加第二条创建记录 |
| 设备事件重复 | 第二次设备回执标记重复 | 唯一键使用设备编号和事件编号 | 信号和关联事件各保留一份 |
| ESP32 离线 | 管理后台可记录“模拟设备离线”事件；硬件路径停止上报 | 恢复硬件前改用 Web 模拟器，页面继续标注“模拟设备信号” | 离线信号作为事件证据保存，不把“离线”误写成老人遇险 |
| 模拟通知失败 | 页面显示“模拟失败”，不会显示“已联系” | HTTP 重放同一请求编号只保留一条；人工重试使用新编号，失败和成功都保留 | `NotificationAttemptRecorded` 和事件联系记录可回读 |
| 后台任务重跑 | 工作台仍只有一条漏签事件和一组到期联系动作 | 任务运行编号和确定性动作编号阻止重复 | 每次任务运行有开始、结束、结果和清理后的错误码 |
| SQLite 写入失败 | API 请求失败；移动端保持“尚未送达”，后台就绪项不能标成 ready | 事务失败时不返回成功。存储恢复后沿用原请求编号重试 | 业务变更与审计在同一事务中，要么一起提交，要么都不提交 |

已运行的自动用例覆盖前七项和 SQLite 可写预检。SQLite 故障分支采用事务设计审查和失败关闭检查；本次没有改动系统目录权限来制造磁盘故障。
